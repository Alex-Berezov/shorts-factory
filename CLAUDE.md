# AI Shorts Factory - правила работы агентов

Internal-first приложение: YouTube trend discovery -> многоязычное производство Shorts
(Source Radar -> Content DNA -> Idea Inbox -> Research -> Script -> Production -> Analytics ->
Experiment Engine -> Localization/TTS -> Publishing). Один репозиторий, pnpm + Turborepo.

Проект разрабатывается **автономно командой агентов**; владелец задачи не ставит и дифф
не читает - он набирает `/auto`, читает отчёт из восьми строк и решает, запускать ли следующую.
Как это устроено - `docs/60_HARNESS.md`; шпаргалка владельца - `docs/61_HOW_TO_WORK.md`.

## Что читать перед любой работой

0. `docs/00_STATUS.md` - где мы: текущая задача, что следующее (генерируется, руками не править).
1. `docs/3x_E?_TASKS.md` того эпика, к которому относится задача, - раздел `### <id>`
   (цель, «Сделать», DoD) и разделы «Архитектурные решения», «Изменения схемы», «Вне скоупа».
2. `docs/20_TZ_HIGH_LEVEL.md` - эпики E0–E13, критерии приёмки, «вне скоупа MVP».
3. `docs/10_SYSTEM_DESIGN.md` - стек, очереди, модель данных, направление зависимостей (§6).
4. `docs/01_ARCHITECTURE.md` - продуктовый blueprint (только нужную секцию).
5. `docs/DECISIONS.md` - что решили PM и техлид до тебя; `.claude/qa-index.md` - уроки ревью.

Документ больше 10 КБ читай секциями: `grep -n "^## " <файл>` -> `Read` с `offset`.

## Роли

| Роль | Агент | Модель | Что делает |
| --- | --- | --- | --- |
| Оркестратор | команда `/auto` | sonnet | ведёт задачу по шагам, кода не пишет, контекст держит коротким |
| Планировщик | `planner` | opus | DoD -> план в файле дела: шаги, файлы, тесты, развилки |
| Продакт | `pm` | fable | продуктовые развилки и UX по документам; о технике не знает |
| Техлид | `techlead` | fable | технические развилки, зависимости, схема, споры ревью; требует ADR |
| Исполнитель | `worker` | sonnet / opus | единственный, кто пишет код; строго по плану, с посадкой тестом |
| Ревьюеры | `review-correctness`, `review-data`, `review-security` | opus | логика; данные и контракты; безопасность |
| | `review-conventions`, `review-tests` | sonnet | стандарты и дисциплина диффа; тесты |
| | `review-architecture`, `review-product` | fable | слои, дубли, имена; DoD и сценарии оператора |

Раскладка моделей - по сложности работы у подагентов (свой кэш, переключение бесплатно)
и по длине контекста у команд (см. `docs/60_HARNESS.md`, «Модели»). Менять - поле `model:`
в шапке файла и `install.ps1`.

## Рабочий цикл (одна задача = одна сессия)

```
/auto          -> next из трекера -> planner -> развилки (pm/techlead) -> worker
               -> /qa (7 ревьюеров + code-review) -> /fix x2 -> gates -> документы
               -> коммит -> tracker done -> отчёт -> СТОП
владелец:      читает отчёт -> /clear -> /auto
```

Ручной режим: `/task` (план) -> `/go` (реализация) -> `/qa` -> `/fix` -> `/done`.
Вопрос PM/техлиду руками: `/ask`. Где мы: `/status`. Проверки: `/gates`.

Трекер задач - `docs/tasks/tasks.json` через `node scripts/tasks.mjs next|start|done|block|add`;
руками файл и `docs/00_STATUS.md` не правятся.

## Что остаётся за владельцем

Пять тем. Список закрытый: расширять и сужать нельзя. Всё остальное решает `pm` или `techlead`,
и только они вправе вернуть вопрос владельцу.

1. **Секреты и аккаунты.** `.env`, ключи API, Google Cloud, консоли провайдеров, OAuth-согласия.
   Агент их не читает, не пишет, не печатает - кроме корневых `.env.example` и `.env.test`:
   исключение действует, только пока файл лежит в корне репозитория под этим точным именем
   и содержит лишь адреса локального Compose и заглушки без настоящих значений; это условие,
   а не разовое разрешение, и каждый дифф этих файлов проверяет security-ревьюер.
2. **Деньги и реальные внешние действия.** Подъём лимитов бюджета/квот в конфиге; платные
   вызовы внешних API сверх смоук-проверок, прямо названных в DoD задачи (bake-off, массовый
   анализ); любое действие на реальном YouTube-канале (публикация, загрузка, настройки);
   выкладка на VPS/прод; разрушительные операции над данными не на локальной базе.
3. **Изменение спецификации.** Цели, скоуп, критерии приёмки в `20_TZ_HIGH_LEVEL.md` и blueprint.
   Уточнение в рамках написанного - PM; смена смысла - владелец.
4. **Смена стека** из `10_SYSTEM_DESIGN.md` §2.
5. **Бренд.** Название канала, маскот, публичное позиционирование.

Локальная база, локальный Docker, файлы миграций, тесты, документация, сама обвязка -
класс «сам»: отменяется `git revert` и следа снаружи не оставляет.

## Hard rules (неизменны)

- TypeScript strict везде; `any` запрещён во всех формах (замок `S01`), клапан `// any-ok: причина (E?-??)`.
- Направление зависимостей: `apps -> packages`; `integrations -> core, config`; `db -> core`;
  `@sf/core` не зависит ни от чего, кроме `zod`.
- Всё асинхронное - идемпотентные BullMQ-джобы с детерминированным `jobId`, ретраями, DLQ;
  каждый внешний вызов пишет стоимость (units/tokens/USD) в `api_usage_log` до возврата.
- YouTube Data API: `search.list` **никогда** (100 units). Синк - uploads playlist, снапшоты -
  `videos.list` батчами.
- Все AI-выводы валидируются Zod (`@sf/core`), хранятся версионированно с `model`,
  `prompt_version`, `cost`. Ничего не перезаписывается - только новые версии.
- Секреты только в `.env` (шаблон `.env.example`); `process.env` читается только в `@sf/config`;
  в web-бандл не попадает ничего секретного.
- Контент: анализируем конкурентов, **не клонируем**. Транскрипты конкурентов не попадают
  в промпты генерации; только абстрактные паттерны.
- Проверки не ослабляются никогда: `continue-on-error`, `|| true`, `--passWithNoTests`,
  `.skip(`, `.only(`, `@ts-ignore`, `biome-ignore` без причины, понижение порога покрытия,
  заглушка в скрипте `lint/test/typecheck/build` - брак, замок `commit-gate` не пустит.
- Каждая правка поведения закрывается тестом, который краснеет без неё; проверено полным
  откатом дефекта. Правка хука - пробой на отказ и на пропуск.
- Зависимости - только по решению `techlead` со строкой в `docs/DECISIONS.md`.
- Никаких упоминаний ИИ в коде, комментариях, коммитах.

## Язык

Код, комментарии, сообщения коммитов - английский. Документы, файлы дела, промпты агентов,
чат с владельцем - русский. В текстах, уходящих наружу (коммиты), только короткий дефис.

## Файл дела и формат ответа

Всё длинное - план, таблица ревью, вывод команд, ход работы - пишется в файл дела
`tasks/<ГГГГ-ММ-ДД>-<id>.md` (путь в `.claude/.task-current`), а не в чат. В чат - отчёт
по `output-styles/short.md`: суть до трёх строк, затем `Задача / Решено за тебя / Проверки /
Обвязка / Дальше`. Хук `answer-length.js` заворачивает длиннее девяти строк; `report-honesty.js`
не пропустит «зелено» без настоящего прогона.

## Обвязка

Лежит в `.claude/`: хуки (`hooks/*.js`), правила (`hooks/rules.common.json`, `hooks/rules.sf.json`),
агенты, команды, стиль ответа. Регистрация хуков - `.claude/settings.json` (коммитится),
персональные разрешения - `.claude/settings.local.json` (пишет `install.ps1`, в `.gitignore`).
Замков на запись файлов нет (решение владельца 06.09.2026): агент правит любые файлы репозитория,
включая обвязку, конвейер и `pnpm-lock.yaml`, столько, сколько нужно задаче. Ошибки ловят
ревьюеры, техлид и замок коммита. Правила без замка: `.env*` не читать и не писать, кроме
корневых `.env.example` и `.env.test` на условиях темы владельца 1, lockfile пишет только
pnpm, применённая миграция не редактируется, конвейер правится только в сторону усиления. После правки обвязки: `powershell -ExecutionPolicy Bypass -File .claude/install.ps1`
и `node .claude/hooks/harness-selftest.js`.
