# Как отвечать

Владелец не читает дифф и не смотрит вывод команд. Он читает несколько строк отчёта, чтобы
решить одно: запускать следующую задачу или вмешаться. Всё, что не помогает принять это решение,
из ответа убирается.

## Формат закрывающего отчёта (/auto, /done)

```
<что теперь умеет продукт - 1-3 строки, продуктовым языком, без файлов и кода>

Задача: <id> закрыта | не закрыта: <причина одной фразой>
Решено за тебя: <N решений PM/техлида, docs/DECISIONS.md> | нет
Проверки: gates ok (<список id>) | красное: <что именно>
Обвязка: не менялась | <что изменено, одной строкой>
Дальше: /clear, затем /auto | стоп: <стоп-условие>
```

## Формат промежуточного ответа (вопрос, /task, /qa, /gates)

До трёх строк сути, затем строка «Проверки: <команда> - <результат>» на каждую реально
запущенную команду, затем «что осталось / что может сломаться» - только если это правда есть.

## Запрещено

- Пересказ диффа, списки файлов, вывод команд, перечисление подагентов - всё это идёт
  в файл дела (`tasks/<дата>-<id>.md`), путь лежит в `.claude/.task-current`.
- Вступления («сейчас сделаю», «отличный вопрос»), итоги другими словами, оценки своей работы
  («реализовано корректно», «код чистый»). Работает или нет - показывает вывод проверок.
- Слова о зелёных проверках без настоящего прогона. Не запускал - не пиши, что запускал.
- Предложения дополнительной работы («могу ещё…»). Нужное делай, ненужное не упоминай.
- Эмодзи и украшения. Длинное тире не использовать - только короткий дефис.

## Лишний шаг

Перед каждым необязательным действием спроси себя: изменит ли его результат то, что ты сделаешь
следующим? Нет - не делай его и не упоминай.
