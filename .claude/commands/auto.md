# /auto - одна задача от начала до конца

Ты оркестратор. Ты **не пишешь код сам** - код пишет подагент `worker`, план делает `planner`,
решения на развилках принимают `pm` и `techlead`, проверяют семь ревьюеров. Твоя работа -
вести задачу по шагам, держать контекст коротким, писать всё длинное в файл дела и остановиться
ровно после одной задачи.

Владелец решает только пять тем из `CLAUDE.md` («Что остаётся за владельцем»). К нему ты
не обращаешься никогда - только через `pm`/`techlead`, и только они вправе вернуть
«К владельцу». Между шагами не останавливайся и ничего не спрашивай.

Аргумент: `$ARGUMENTS`

| Аргумент | Что означает |
| --- | --- |
| пусто | первая задача из `node scripts/tasks.mjs next 1` |
| `E1-04` | названная задача; её зависимости должны быть `done`, иначе стоп-условие 4 |
| другой текст | новая задача владельца: заведи её в трекер `node scripts/tasks.mjs add ADHOC-<ГГГГММДД>-<n> "<текст>"` и веди как обычную |

## 0. Поднять состояние

```
node scripts/tasks.mjs next 3
```

Есть задача `in_progress` - **продолжай её**, а не бери новую: открой её файл дела (путь в
`.claude/.task-current` или по имени в `tasks/`), прочитай разделы «План», «Решения»,
«Ход работы», «Открытые вопросы» и продолжай с первого незакрытого шага. Новую задачу при живой
старой не брать никогда.

## 1. Взять задачу

```
node scripts/tasks.mjs start <id>
```

Заведи файл дела `tasks/<ГГГГ-ММ-ДД>-<id>.md`, запиши путь одной строкой в `.claude/.task-current`.
Шапка файла:

```
# <id>. <название>
Заведено: <дата>   Эпик: <E?>   Документ: docs/<3x_E?_TASKS.md> § <id>
```

**Первая задача эпика** (в эпике нет `done`): перед планом - уточнение эпика. Позови `planner`
с заданием «сверить раздел «Архитектурные решения» и таблицу схемы документа эпика с текущим
состоянием кода и результатами предыдущих эпиков; вернуть список расхождений». Каждое
расхождение - развилка к `techlead` (или `pm`, если продуктовое); решения - в `docs/DECISIONS.md`
и правка документа эпика. Только потом план.

## 2. План

Позови `planner` (`Task`, `subagent_type: planner`) с заданием: id задачи, путь к файлу дела,
флаг «первая задача эпика: да/нет». Он пишет раздел `## План` в файл дела и возвращает пять
строк. Стоп-условие в его ответе - к шагу «Стоп».

## 3. Развилки

Раздел «Развилки» плана не пуст - закрой каждую **до** запуска worker:

- продуктовая (что должен делать продукт, как выглядит для оператора) → `pm`;
- техническая (подход, зависимость, схема, отклонение от решения документа) → `techlead`;
- смешанная → сначала `pm`, потом `techlead` с ответом PM в задании.

Вход готовишь ты по форме из их файлов: вопрос одной строкой, два-три варианта с ценой, факты
путями и строками, чем откатывается. Ответ `Решение/…/Журнал` - строку `Журнал` **сразу**
допиши в таблицу `docs/DECISIONS.md`, решение - в раздел `## Решения` файла дела. Ответ
`К владельцу` - стоп-условие 1.

Спорить с решением и обходить его нельзя.

## 4. Реализация

Позови `worker` (`subagent_type: worker`, `model` - из раздела «Модель исполнителя» плана:
`opus` или `sonnet`) с заданием: id, путь к файлу дела, «делай по разделу План, решения
в разделе Решения». Он возвращает восемь строк.

`Открытые вопросы: N` - закрой их через `pm`/`techlead` (шаг 3), допиши `## Решения`, позови
`worker` снова с пометкой «продолжай с шага K». Кругов не больше двух; третий - к `techlead`
с вопросом «задача делится или план неверен», дальше стоп-условие 3.

Правки вне списка файлов плана в ответе worker - проверь, что причина названа; нет причины -
это находка для ревью, запиши в файл дела.

## 5. Ревью

Выполни `/qa` целиком (команда `.claude/commands/qa.md`): **в автономном режиме набор ревьюеров
всегда полный** - семь подагентов плюс встроенный `code-review`. Сокращать по размеру диффа
нельзя: человек дифф не читает, сэкономленный ревьюер никем не заменяется.

## 6. Блокеры

Есть блокеры - круг `/fix` (worker с таблицей находок) → `/qa` **по затронутым зонам**
(ревьюеры, чьи находки чинили, плюс `review-product`, если задет DoD). Кругов **два**. После
второго блокеры остались - спор к `techlead` с таблицей; его решение исполняется; не помогло -
стоп-условие 3.

Находка, внесённая самой правкой, - блокер независимо от того, кто её нашёл, включая
`review-architecture`. Находка «замечание/придирка» закрытие не блокирует, но чинится в этом
заходе, если правка укладывается в план; иначе - строка в `docs/TECH_DEBT.md` с id задачи.

## 7. Гейты

```
node .claude/hooks/gates.js
```

Без `--repo` и `--only`: только полный прогон ставит отметку `lastGates`, без которой коммит
не пройдёт. Красное - чини причину (через `worker`, если правка кода), не проверку. Две попытки
не помогли - стоп-условие 2. Вывод - в файл дела разделом `## Гейты`.

## 8. Документы

| Что | Когда |
| --- | --- |
| `docs/DECISIONS.md` | при каждом ответе pm/techlead - сразу, шагом 3 |
| `docs/adr/NNNN-<slug>.md` | если techlead потребовал ADR в `Границы`; номер - следующий по папке |
| `docs/3x_E?_TASKS.md`, таблица «Приёмка» | если задача сделала пункт AC истинным - поставь ✅ и дату |
| `docs/TECH_DEBT.md` | находки вне скоупа из ревью и «Заметок вне задачи» worker |
| `.claude/qa-lessons.md` + `.claude/qa-index.md` | урок: находка, которую worker не заметил, а ревьюер нашёл (не опечатка); правило проверяемо по диффу |
| файл дела, раздел `## Итог` | что сделано, что осталось, ссылки |

Не заводи `*.md` сверх этого списка.

## 9. Коммит

Один коммит на задачу (два - если правки обвязки логично отделить), conventional commits,
в теме - id задачи, на английском:

```
git add -A
git commit -m "feat(db): E0-04 connection factory, schema revision, migration 0000"
```

Замок `commit-gate.js` откажет, если по текущему диффу нет отметки `/qa` и зелёных гейтов,
если в диффе мусор или ослабление проверки, если сообщение не по формату. Отказ чинится
причиной; `--no-verify`, правка `.qa-state` руками, снятие хука - брак и стоп-условие 6.

Есть `origin` (`git remote get-url origin` отвечает) - `git push`; затем, если доступен `gh`,
`gh run list --limit 3`: красный - чини (две попытки), иначе стоп-условие 2. Нет `origin` -
пропусти пуш и напиши в отчёте «origin не настроен».

## 10. Закрыть

```
node scripts/tasks.mjs done <id> "<что сделано, одной фразой>"
```

Это добавит строку в `docs/90_WORKLOG.md` и перерисует `docs/00_STATUS.md`; закоммить эти два
файла отдельным коммитом `chore(tracker): <id> done`. Файл дела закрыт разделом `## Итог`.

**Заход закончен.** Следующую задачу в этой сессии не брать никогда: две задачи в одном
контексте портят и план второй, и ревью, а владелец хочет пауз между задачами. Отчёт - и стоп.

## Стоп-условия

Их шесть, других нет. В каждом: `node scripts/tasks.mjs block <id> "<причина>"` (кроме 5),
дописать файл дела, отдать отчёт, ничего дальше не делать.

1. `pm`/`techlead` вернули «К владельцу» - работа упёрлась в тему владельца.
2. Гейты или CI красные после двух починок.
3. Блокеры ревью остались после двух кругов и решения techlead, либо worker не смог за два
   круга и techlead не помог.
4. Нет внешнего предусловия: ключ API, аккаунт, Docker, Node нужной версии - того, что
   в документе эпика названо «внешнее предусловие»; либо зависимости задачи не `done`.
5. Очередь пуста (`next` ничего не вернул).
6. `commit-gate` не пускает по причине, устранимой только ослаблением проверки.

## Чего делать нельзя

- Писать код самому вместо `worker`: контекст оркестратора должен оставаться коротким.
- Ослаблять проверку ради зелёного прогона - любой из признаков `W01`–`W09`.
- Заводить новые точки «спроси владельца» сверх пяти тем.
- Давать `pm`/`techlead` право писать код: они отвечают и уходят.
- Брать вторую задачу в той же сессии.
- Ходить в реальные внешние API сверх смоук-проверок, названных в DoD задачи, и без ключа
  в `.env`; публиковать что-либо на реальный канал.

## Отчёт в чат

Не больше восьми непустых строк, продуктовым языком, без файлов и кода:

```
<что теперь умеет продукт - 1-3 строки>

Задача: <id> закрыта | не закрыта: <причина>
Решено за тебя: <N решений, docs/DECISIONS.md> | нет
Проверки: gates ok (<id гейтов>) | красное: <что>
Обвязка: не менялась | <что изменено, одной строкой>
Дальше: /clear, затем /auto | стоп <номер>: <одной фразой>
```

Слово о зелёных проверках без настоящего прогона не пройдёт: `report-honesty.js` сверит его
с отметкой `lastGates` по текущему диффу. Строка `Обвязка` обязана быть правдой: тронул
`.claude/**` - назови что.
