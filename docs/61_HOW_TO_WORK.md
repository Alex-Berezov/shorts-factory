# Как работать с проектом: шпаргалка владельца

_Разработку ведёт команда агентов. Ты набираешь одну команду, читаешь восемь строк и решаешь,
запускать ли следующую задачу. Подробности устройства - `60_HARNESS.md`._

## Коротко

| Что мне нужно | Что набрать |
| --- | --- |
| Сделать следующую задачу по трекеру | `/auto` |
| Сделать конкретную задачу | `/auto E1-04` |
| Новая задача своими словами | `/auto сделай так, чтобы …` (заведётся как ADHOC в трекере) |
| Посмотреть план до старта | `/task E1-04`, потом `/go` |
| Продукт ведёт себя не так | `/fix <что не так, словами>` |
| Спросить PM или техлида | `/ask <вопрос>` |
| Где мы сейчас | `/status` или открыть `docs/00_STATUS.md` |

Между задачами - **`/clear`**. Одна задача = одна сессия: агент сам следующую не берёт.
Сессию держать на sonnet (`/model sonnet`): дорогие модели подключаются сами там, где нужны.

## Что происходит по `/auto`

Агент берёт первую задачу с выполненными зависимостями, планирует, закрывает развилки через
PM и техлида, пишет код и тесты, гоняет семь ревьюеров и встроенное ревью, чинит блокеры
(два круга), гоняет проверки, обновляет документы, коммитит, отмечает задачу в трекере -
и останавливается. В чате - не больше восьми строк:

```
<что теперь умеет продукт>

Задача: E0-04 закрыта
Решено за тебя: 2 решения, docs/DECISIONS.md
Проверки: gates ok (lint, typecheck, test, build, no-search-list)
Обвязка: не менялась
Дальше: /clear, затем /auto
```

Ни диффов, ни списков файлов, ни вывода команд в чате - всё в файле дела `tasks/<дата>-<id>.md`.

## Кто решает вместо меня

- **PM** (`.claude/agents/pm.md`) - что должен делать продукт и как выглядит для оператора,
  строго по `01_ARCHITECTURE.md`, `20_TZ_HIGH_LEVEL.md` и документам эпиков. О технике не знает.
- **Техлид** (`.claude/agents/techlead.md`) - подход, зависимости, схема, споры ревьюеров,
  красное после двух починок. Требует ADR на структурные решения.

Оба пишут строку в `docs/DECISIONS.md` сразу после ответа. Это единственный документ, который
стоит открыть, чтобы увидеть, что нарешали без тебя. Не согласен с решением - `/fix` словами
или `/ask` с своим вариантом: решение пересматривается, а не остаётся навечно.

## Пять тем, которые остались за мной

1. **Секреты и аккаунты** - `.env`, ключи, Google Cloud, OAuth-согласия.
2. **Деньги и реальный мир** - подъём лимитов; платные вызовы сверх смоук-проверок из DoD;
   всё на реальном YouTube-канале; выкладка на сервер.
3. **Изменение спецификации** - цели, скоуп, критерии приёмки.
4. **Смена стека.**
5. **Бренд.**

Упёрлась задача в одну из тем - агент блокирует её в трекере с причиной и останавливается.
Дать то, чего не хватает (ключ в `.env`, решение словами), - и `/auto` снова: задача
разблокируется командой `node scripts/tasks.mjs unblock <id>` или сам агент увидит предусловие.

## Когда агент останавливается сам

Шесть стоп-условий: тема владельца; красные проверки/CI после двух починок; блокеры ревью после
двух кругов и техлида; нет предусловия (ключ, Docker, Node 22); очередь пуста; замок коммита
не пускает без ослабления проверки. В каждом случае в отчёте - `Дальше: стоп N: <почему>`,
задача в трекере - `blocked`.

## Что стережёт качество вместо меня

- **Перед записью файла** - ничего: замки на пути и рамки задачи сняты 06.09.2026, агент правит
  любые файлы, а ошибки ловят ревьюеры, техлид и замок коммита.
- **После записи** - стандарты по добавленным строкам (`any`, `console`, `process.env`,
  `search.list`, границы пакетов…).
- **Перед коммитом** - ревью по этому самому диффу, зелёные проверки, нет мусора и ослаблений,
  сообщение по формату.
- **Перед ответом мне** - длина, честность про «зелено», честность про правки обвязки.

Семь ревьюеров на каждую задачу: логика, данные, безопасность, соглашения, тесты, архитектура,
продукт (сверка с DoD и спецификацией) - плюс встроенное ревью.

## Внешние предусловия по эпикам

Их надо дать заранее, иначе задача встанет по стоп-условию 4:

| Когда | Что |
| --- | --- |
| E0-01 | Node 22 на машине (сейчас v20), pnpm, Docker Desktop |
| E0-11 | Docker Desktop с WSL2 |
| E1 | Google Cloud проект, YouTube Data API v3, API key -> `.env` `YOUTUBE_API_KEY` |
| E2 | Gemini API key с биллингом -> `GEMINI_API_KEY` |
| E7 | OAuth client, YouTube Analytics API -> `GOOGLE_CLIENT_ID/SECRET`, `TOKEN_ENCRYPTION_KEY` |
| E10 | ключи TTS-провайдеров, `ffmpeg` |
| E11 | scope `youtube.upload`, статус OAuth-приложения |
| любой | `git remote add origin …` - до этого пуш и CI пропускаются с пометкой в отчёте |

## Если правил обвязку

```powershell
powershell -ExecutionPolicy Bypass -File .claude/install.ps1
```

Снимок, сверка моделей, `settings.local.json`, самопроверка. Стало хуже - `.claude/otkat.ps1`
или `git checkout -- .claude/<файл>`. После установки - `/clear`.

## Файлы, которые стоит знать

| Файл | Что там |

| `docs/TECH_DEBT.md` | что заметили, но не чинили |
