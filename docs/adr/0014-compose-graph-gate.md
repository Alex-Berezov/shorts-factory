# ADR-0014: гейт compose проверяет тот же граф и ту же интерполяцию, что поднимает оператор

Дата: 2026-10-20   Статус: принято   Задача: E0-12K (решения техлида по развилкам 1-4 E0-12K 20.10.2026, `docs/DECISIONS.md`; пересмотр Р4 E0-12A; источник - E0-12C, стоп 3, решение D)

## Контекст

Гейт `check-compose` рендерит `docker compose -f compose.yaml config` с пустым env-файлом и
проверяет правила 0-13 на этом JSON. Оператор же запускает `docker compose up` без `-f`, из
своей оболочки и со своим `.env`. В E0-12C четыре круга ревью находили, чем стек оператора
отличается от проверенного: override-файлы, которые Compose подмешивает без `-f` (четыре имени
compose-go, в корне и в `infra/`), `include`/`extends: file:` на файл вне маски `when`, формы
YAML, которых не видел построчный читатель (ключ в кавычках, flow, BOM, escape, второй
документ, теги), `${X}` в пути, симлинк, интерполяция `${VAR:-default}` из `.env`, профили,
`COMPOSE_FILE`/`COMPOSE_PROFILES` и переменные графа в окружении оболочки. Решение D вынесло
это в E0-12K; замеры на Compose 5.5.1 - `tasks/2026-10-20-E0-12K.md`, «Замеры».

## Решение

- **Граф - из разбора `yaml`.** `yaml@2.9.0` точным пином в корневых devDependencies
  (развилка 1; пересмотр Р4 E0-12A «`yaml` не вводится»). Только `scripts/**` и `test/**`,
  не `packages/*`/`apps/*`. Читатель графа `scripts/lib/compose-graph.mjs` (`composeGraph`;
  перечень файлов стека `COMPOSE_SOURCES` - в `scripts/compose-rules.mjs`, читателю он
  передаётся предикатом `admits`) обходит корневой файл, `include` (строка, `{path}`,
  `path:` списком) и `services.<имя>.extends.file` по каноническим путям, каждый файл
  один раз; файл, который `admits` не берёт (по записанному пути или по realpath), не
  открывается - его ребро остаётся правилу 15. Разбор fail-closed: больше одного документа,
  `errors`/`warnings` парсера (неизвестные теги `!reset`/`!override`), корень не мэппинг,
  иная форма `include`/`extends`, `project_directory`/`env_file` в `include`, путь с `$`,
  цель, которой нет, циклический alias, alias сверх `maxAliasCount` или значение, которое
  парсер не строит (merge-ключ не на мэппинг), - нарушение с файлом, полем и причиной
  парсера. Merge-ключ `<<` раскрывается (`merge: true`), как у Compose.
- **Правило 14 - override не поддерживается.** Ни одного из `OVERRIDE_FILES` в каталоге
  корня и в каталоге любого файла графа. Там же нет файла с другим именем, которое Compose
  ищет без `-f` (`DEFAULT_FILES`: `compose.yaml`, `compose.yml`, `docker-compose.yml`,
  `docker-compose.yaml`), если он не файл графа: `infra/compose.yaml` поднял бы
  `cd infra && docker compose up` вместо `infra/docker-compose.yml` (Compose берёт первый
  найденный, замер). Нет `.env` рядом с файлом графа вне корня: Compose читает его для
  интерполяции этого файла поверх `--env-file` (замер). Проверяется только существование
  (realpath), содержимое не читается.
- **Правило 15 - граф = файлы `when`.** Каждый файл графа - один из `COMPOSE_SOURCES`
  (`compose.yaml`, `infra/docker-compose.yml`, `infra/docker-compose.app.yml`) и по
  записанному пути, и по realpath; проблемы читателя - нарушения этого правила. `when`
  гейта - ровно читаемые файлы: три файла графа, четыре имени override и прочие имена
  `DEFAULT_FILES` в корне и в `infra/`, `.dockerignore` и
  `infra/docker/app.Dockerfile.dockerignore` (их читает правило 11 по сборкам стека),
  `.env.test`, `package.json` (пин `yaml`), скрипты гейта и `scripts/lib/{compose-graph,yaml-doc,files,json,paths}.mjs` (`yaml-doc.mjs` - `readYaml`, fail-closed разбор, которым `compose-graph.mjs` читает файлы графа; E0-12N).
  `infra/.env` в `when` нет: файл в `.gitignore`, а `gates.js` берёт изменения из git, так
  что выбор на нём не срабатывал бы никогда; правило 14 находит его на любом прогоне гейта.
  Сверку `when` с `COMPOSE_SOURCES`, `OVERRIDE_FILES`, `DEFAULT_FILES` и `.dockerignore`
  сборок держит `test/compose-rules.test.ts` через `selectGates` из `gates.js` (свой разбор
  синтаксиса `when` тест не держит); выбор, пропуск, видимость файлов выбора для git и
  точность масок (соседи файла выбора гейт не выбирают) - `harness-selftest.js`.
- **Правило 16 - профилей нет.** Рендер идёт с `--profile '*'`, поэтому сервис за профилем
  доходит до правил; поле `profiles` у любого сервиса - нарушение.
- **Правило 17 - значения только из файлов графа.** Правило читает корни файлов графа,
  которые разобрал `composeGraph` (`roots`), а не разбирает YAML заново. Голый ключ
  `services.*.environment` (элемент списка без `=`, ключ мэппинга со значением `null`) Compose
  заполняет из `.env` или оболочки, а `--variables` его не называет (замер на Compose 5.5.1:
  `FOO: null` против `FOO: "fromenvfile"`) - значение ушло бы в контейнер мимо env-файла
  гейта; это нарушение. Верхние `configs` и `secrets` в любой форме (`file`, `environment`,
  `content`, `external`) и `services.*.label_file` берут значения вне файлов графа; в стеке
  их нет, и они - нарушение, как `env_file` для правила 10, а не новые рёбра графа.
- **Интерполяция без `.env`** (развилка 2). `config --variables --format json` с пустым
  env-файлом называет переменные графа. Каждая должна быть в `INTERPOLATED`
  (`scripts/compose-rules.mjs`), не `Required` и с умолчанием, не равным контрольному
  значению; иначе нарушение до рендера. Затем рендер с пустым env-файлом (его проверяют
  правила) и контрольный рендер, где каждой переменной дано её контрольное значение.
  `checkInterpolation` сравнивает листья двух JSON: поле, которое изменилось, должно
  содержать контрольное значение переменной (целиком или одну его часть между `:` -
  адрес или порты, на которые Compose делит публикуемый порт) и быть одним из её полей.
  Контрольное значение имеет все формы, которые значение из `.env` может принять на своём
  месте, поэтому контрольный рендер показывает каждое поле, куда такое значение
  дотягивается. Перечень: `WEB_PORT` - `services.web.ports[*].host_ip` и
  `services.web.ports[*].published` (контроль - `127.0.0.2:39871-39872`: адрес и диапазон;
  замер: `${WEB_PORT:-3000}:3000` с `0.0.0.0:3000` даёт `host_ip` и `published`, с
  `3000-3010` - диапазон в `published`; правило 1 и так выпускает web на любом адресе),
  `APP_VERSION` и `GIT_COMMIT` - `services.*.build.args.<имя>` (контроль - слово, которого
  нет в файлах). Причина перечня: только эти три переменные стек берёт из `.env`
  оператора (порт и адрес web на хосте, метки сборки); любое другое место подстановки
  (порт postgres, healthcheck, `environment`) уводит стек мимо правил 1/8/12. Новая
  переменная добавляется только правкой перечня с кейсом. Сообщения - путь поля и имя переменной,
  без значений и без вывода docker (Т7 E0-12G).
- **Окружение вызова docker** (развилка 3). Копия окружения гейта по именам, без всех
  `COMPOSE_*`, а для рендеров - и без переменных графа; на win32 имена сравниваются без
  учёта регистра (Windows читает `Compose_File` как `COMPOSE_FILE`, замер). `DOCKER_*` и
  остальное остаются: белый список теряет плагин compose на Windows (замер планировщика).
  Любая непустая `COMPOSE_*` в окружении гейта, кроме перечня безвредных `HARMLESS`
  (`scripts/check-compose.mjs`: `COMPOSE_ANSI`, `COMPOSE_PROGRESS`, `COMPOSE_STATUS_STDOUT`,
  `COMPOSE_MENU`, `COMPOSE_PARALLEL_LIMIT`, `COMPOSE_IGNORE_ORPHANS`,
  `COMPOSE_REMOVE_ORPHANS` - вывод и поведение команд, не состав стека), - красный до запуска
  docker, с именем переменной без значения: `docker compose up` из той же оболочки поднял бы
  другой стек (`COMPOSE_FILE`, `COMPOSE_PROFILES`, `COMPOSE_ENV_FILES` - замер;
  `COMPOSE_PROJECT_NAME`, `COMPOSE_DISABLE_ENV_FILE` и `COMPOSE_*` будущих версий Compose -
  тем же правилом, без снятия молча). Пустое значение - как не заданное. Безвредная
  `COMPOSE_*` из окружения docker снимается, как и прочие.
- **`.env` гейт не читает** (решение 18.10.2026 сохраняется). `COMPOSE_FILE`,
  `COMPOSE_PROFILES`, `COMPOSE_PROJECT_NAME` в `.env` оператора гейт не видит - строка
  `docs/TECH_DEBT.md` на E1-12 (решение R1 E0-12C).
- Мёртвые ветки `ETIMEDOUT`/`ENOENT` в `endingOf` сняты (развилка 4), предел времени гейтам -
  E0-12M.

## Альтернативы

- Рукописный построчный читатель (развилка 1, B) - четыре круга E0-12C показали рост
  обходов (L-028); байтовый эталон `compose.yaml` (C) ломается от любой правки и запрещает
  легальный `extends`.
- `--no-interpolate` (развилка 2, B) - правила пришлось бы учить сырой форме `ports` и
  healthcheck; перечень имён без места (C) пропускает `WEB_PORT` в `ports` postgres.
- Молча снимать `COMPOSE_*` и оставаться зелёным (развилка 3, B) - прячет расхождение стека
  гейта и оператора; белый список окружения (C) - теряет плагин compose на Windows.
- Широкая маска `infra/**` (решение D E0-12C) - выбирала гейт на файлах, которых он не
  читает, и не выбирала файл вне `infra/`, подключённый `include`.

## Последствия

- Новый Compose-файл стека добавляется в трёх местах сразу: `include` корня,
  `COMPOSE_SOURCES` и `when` гейта (и mustRun пробы selftest); без этого гейт красный
  правилом 15. Override для локальных правок не поддерживается - правится сам файл стека.
- Новая переменная интерполяции - строка `INTERPOLATED` с контрольным значением, полями и
  кейсом; без неё гейт красный до рендера. Ложный красный не ослабляют: перечень и есть
  граница, причина которой записана выше.
- Гейт делает четыре вызова docker вместо двух (проба, переменные, рендер, контрольный
  рендер), все без демона.
- Известный остаток: `--variables` отдаёт одно умолчание на переменную; вторая подстановка
  той же переменной с умолчанием, равным контрольному значению, контрольным рендером не
  видна (замер, «Замеры» файла дела E0-12K). Остаток держит кейс `test/compose-rules.test.ts`
  («known gap accepted by decision (ОВ1, ADR-0014): does not see a second use of a variable
  whose default is its control value»): гейт,
  который начнёт его видеть, краснеет этим кейсом, и запись правится вместе с ним.
- Создание `infra/.env` само по себе гейт не выбирает (`.gitignore`); правило 14 найдёт
  файл при следующем прогоне гейта на любом из файлов `when`; в CI такого файла нет.
- Подъём версии `yaml` - правка `package.json`, на которой выбирается гейт; пин точный,
  тест держит `2.9.0`.
