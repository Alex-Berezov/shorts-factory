## Цикл одной задачи

```
владелец: /auto
  0  next из трекера; продолжить in_progress, если есть
  1  start <id>; файл дела; первая задача эпика -> уточнение решений эпика (planner -> techlead/pm)
  2  planner (opus): DoD -> план в файл дела (шаги, файлы, тесты, риски, допущения, развилки, модель worker)
  3  развилки -> pm (продукт) / techlead (техника), fable; решение -> docs/DECISIONS.md сразу
  4  worker (sonnet|opus по плану): код + посадка тестом; открытые вопросы -> шаг 3 -> worker (<=2 круга)
  5  /qa: 7 ревьюеров параллельно + встроенный code-review high; таблица в файл дела
  6  блокеры -> /fix (worker) -> /qa по зонам, два круга; спор -> techlead
  7  gates.js полностью (lint, typecheck, test, build, no-search-list, tracker, harness); отметка lastGates
  8  документы: DECISIONS, ADR, приёмка эпика, TECH_DEBT, уроки
  9  commit (conventional, id в теме); push и CI - если есть origin
  10 tasks.mjs done; отчёт 8 строк; СТОП. Следующая задача - новая сессия после /clear
```

Стоп-условий шесть (`commands/auto.md`): тема владельца; красные гейты/CI после двух починок;
блокеры после двух кругов и техлида; нет внешнего предусловия; очередь пуста; замок коммита
не пускает без ослабления. Во всех - `tasks.mjs block <id> "<причина>"`, отчёт, стоп.

## Почему такие роли

- **PM и техлид вместо одного арбитра.** Владелец хочет, чтобы продуктовые вопросы решались
  строго по документации, без знания техники, а технические - с учётом продукта. Один агент
  на обе роли смешивал бы аргументы; два - дают чистое разделение и понятный журнал («PM решил
  X», «техлид решил Y»). Подагент не может позвать подагента, поэтому связку «PM, потом техлид
  с ответом PM» собирает оркестратор.
- **Worker отдельно от оркестратора.** Оркестратор на sonnet держит короткий контекст
  (координация, таблицы, решения), а код пишется в свежем контексте подагента с планом на входе.
  Это и экономия (оркестратор не таскает прочитанные файлы через весь заход), и качество
  (worker не отвлекается на ход ревью).
- **Семь ревьюеров.** Четыре из newDev (логика, данные, соглашения, тесты) плюс три под задачи
  этого проекта: безопасность (ключи внешних API, деньги), архитектура (портфолио-требование
  владельца), продукт (проигрывание DoD по коду - то, что в AVA делает `ava-review-scenario`
  и что ловит класс дефектов, невидимый чек-листам).

## Модели

| Модель | Кто | Почему |
| --- | --- | --- |
| fable | `pm`, `techlead`, `review-architecture`, `review-product` | решения вместо человека и суждение о замысле - самое дорогое место для ошибки; вызываются редко (единицы раз на задачу) и на коротком контексте |
| opus | `planner`, `review-correctness`, `review-data`, `review-security`, `worker` на рискованных задачах | глубокое чтение кода и логика; свой контекст у каждого |
| sonnet | `/auto` и остальные команды, `worker` по умолчанию, `review-conventions`, `review-tests` | дисциплина, а не глубина; дисциплину держат хуки |

Правило из «Экономия токенов - принципы»: у подагентов свой кэш - модель выбирается по
сложности честно; у команд главной сессии смена модели перечитывает всю историю по цене записи,
поэтому дорогая модель у команды стоит только там, где команда идёт первым ходом после `/clear`
(`/task` на opus). `/auto` идёт на sonnet и держит контекст коротким за счёт подагентов.
Сессию держать на одной модели (`/model sonnet`), между задачами - `/clear`.

Когда `worker` идёт на opus (решает planner в разделе «Модель исполнителя»): схема БД и
миграции, деньги и квоты, идемпотентность джобов, авторизация и секреты, конкурентность.
Правка вёрстки, текстов, конфигов, документации - sonnet.

## Замки

| Замок | Что не пускает | Как снять законно |
| --- | --- | --- |
| `standards` | добавленные строки с `any`, `console.*`, `process.env` вне config, `search.list`, относительный импорт пакета, `TODO` без id, `biome-ignore` без причины … (S01–S16, W01–W08); S13/S14 - форма роута в `apps/api/src/routes/**` (регистрация только `defineRoute`, без `.get(`/`.route(`/`withTypeProvider` на любом получателе; `defineRoute` в файле с `...errorResponses()` в коде; точные статусы - `apps/api/test/route-shape.test.ts`), S15/S16 - направление `contracts -> core`, `api-client -> contracts` по импортам (`from`, побочный `import`, `import("…")`, `require("…")`; все формы и манифесты - `test/dependency-direction.test.ts`) | починить строку; клапан `any-ok:`/`console-ok:`/`env-ok:` с причиной - и слово в отчёте |
| `commit-gate` | коммит без отметки `/qa` по этому диффу, без зелёных гейтов, с мусором, с ослаблением (W01–W09), с `--no-verify`/`--force`, не по conventional commits | сделать то, чего не хватает; обход - брак |
| `report-honesty` | «проверки зелёные» без `lastGates{code:0}` по текущему диффу; «Обвязка: не менялась» при тронутых `.claude/**` | прогнать гейты или написать правду |

Рекомендательные хуки - не замки, ничего не запирают (решение владельца 03.10.2026 в
`docs/DECISIONS.md`). `answer-length` (Stop) меряет каждый ответ, в том числе переписанный
после отказа `report-honesty`; ответ длиннее 9 непустых строк или 900 знаков прозы не
переписывается (владелец увидел бы его дважды), а замечание ложится в состояние под номером
сессии (`lengthNotes`, не больше 8 сессий, вытесняется старейшая; без `session_id` не
пишется). `remind-format` (UserPromptSubmit) отдаёт агенту только замечание своей сессии
в начале её следующего хода и снимает его; замечания других сессий не трогает. Значит,
замечание работает только в многоходовой сессии: в `/auto` за отчётом идёт `/clear`, и до
новой сессии оно не доходит - длину отчёта там держит форма `auto.md` и
`output-styles/short.md` (решение техлида 03.10.2026). На длинной сессии `remind-format`
дописывает и памятку формата.

`SF_HOOK_STATE_DIR` - служебная переменная самопроверки: `harness-selftest.js` ставит её
во временную папку на весь прогон, и хуки в пробах пишут состояние туда, а не в боевой
`.claude/.qa-state`. До первой пробы selftest снимает байты боевого файла (или отмечает,
что его нет), последняя проба сравнивает их с текущими: хук, записавший в боевой файл,
делает её красной. Пишущая в тот же файл соседняя сессия тоже даст красное - тогда прогон
повторяется. Папка убирается на выходе selftest, в том числе по Ctrl+C. Читает переменную
только `lib.js:statePath()`; в работе хуков она не задаётся.

Замков на запись файлов нет - решение владельца 06.09.2026: `protect-files` (защищённые пути,
`unlock.txt`), `scope` (рамки задачи, `scope.txt`), `diff-boundaries` (парные правки X01/X02)
и `qa-lock` (счётчик правок без `/qa`) сняты, потому что каждый запуск `/auto` останавливался
на них раньше плана. `/qa` по-прежнему обязателен перед коммитом - это держит `commit-gate`. Агент правит любые
файлы; ошибки ловят семь ревьюеров, техлид и замок коммита.

Все замки fail-closed: упавший хук отказывает и называет причину, а не молча пропускает.
Отпечаток диффа считается в одном месте (`diff-hash.js`) от списка файлов, поэтому отметки
`/qa` и гейтов переживают коммит и не открывают замок другому диффу.

## Гейты

`node .claude/hooks/gates.js` читает `rules.sf.json`:

| id | команда | когда |
| --- | --- | --- |
| lint | `pnpm lint` | всегда |
| typecheck | `pnpm typecheck` | всегда |
| test | `pnpm test` | всегда (E0-02A); повторы снимает кэш turbo |
| test:int | `pnpm test:int` | изменено то, что читают int-тесты: граф int-пакетов, корневые конфиги и `.env.test` (точный glob - гейт `test:int` в `rules.sf.json`, E0-02A); нужен поднятый Compose (`infra/docker-compose.yml`), без него красный |
| build | `pnpm build` | изменено то, что читает `next build`: `apps/web/**`, `packages/{api-client,config,contracts,core}/**`, корневые `package.json`, `pnpm-workspace.yaml`, `pnpm-lock.yaml`, `turbo.json`, `tsconfig*.json` (E0-01A) |
| no-search-list | `node scripts/check-no-search-list.mjs` | всегда |
| compose | `node scripts/check-compose.mjs` (= `pnpm check:compose`) | изменены файлы, которые гейт читает (E0-12C): ровно - `.dockerignore`, корневой `.env.test`, `scripts/check-compose.mjs`, `scripts/compose-rules.mjs`, `scripts/lib/paths.mjs` (корень, `canonical`, `isEntry`), `scripts/lib/files.mjs` (`readIfFile`, `isGone`, `codeOf`); Compose-файлы - широкой маской `compose*.{yml,yaml}` и `docker-compose*.{yml,yaml}` в корне и весь `infra/**` (вместе с `<Dockerfile>.dockerignore`, а также README, скриптами бэкапа, init-SQL и Dockerfile, которые гейт не читает; сужение до графа include/override - E0-12K). Нужен Docker CLI с Docker Compose 5.x (CI держит 5.5.1; 2.x красный намеренно - 2.38 теряет `create_host_path: false`, `infra/README.md`), демон не нужен; `.env` не читает, читает `.dockerignore` и `.env.test` (адреса локального Compose). Правила - `scripts/compose-rules.mjs`; среди них `restart: unless-stopped` у всех сервисов, кроме `migrate` (поэтому dev-postgres/redis поднимаются вместе с Docker Desktop), `.env` проекта, смонтированный в `migrate`/`api`/`worker`/`web` в `/repo/.env` read-only с `create_host_path: false`, без `env_file` (Р9), включённый healthcheck у Postgres (правила 4 и 8; `pg_isready` - ровно одно `-h` с loopback `127.0.0.1`/`localhost`/`::1`, `-p` нет или `5432`), публикация портов `.env.test` только по TCP (правило 12) и правило 11: `.dockerignore` контекста сборки каждого образа маскирует `.env`, `.env.*`, `**/.env`, `**/.env.*`, после первой маски нет ни одной `!`-строки, рядом с Dockerfile нет `<Dockerfile>.dockerignore`. Манифесты `apps/*/package.json` гейт не проверяет |
| tracker | `node scripts/tasks.mjs render --check` | изменены `docs/tasks/**`, `docs/00_STATUS.md`, `scripts/tasks.mjs`, `scripts/lib/**` |
| harness-selftest | `node .claude/hooks/harness-selftest.js` | изменены `.claude/**` или файлы проекта, которые читают пробы гейтов `build` и `test:int` (манифесты, конфиги сборки и int-тестов, `.env.test`): они сверяют их с glob этих гейтов; для `test:int` проба требует, чтобы каждый прочитанный ею файл выбирал `harness-selftest` (для `build` такой сверки нет - переадресовано E0-12L (Р3 E0-12D, 19.10.2026; было: долг E0-12D)). Ещё - файлы, названные в `note` гейтов `compose` и `tracker`, которых нет в `when`/`cmd` самого гейта (`test/compose-rules.test.ts`, `test/container.test.ts`): проба сверяет пути `note` с диском и требует, чтобы каждый такой файл выбирал `harness-selftest`; `docs/00_STATUS.md`, `scripts/tasks.mjs`, `scripts/lib/**` его не выбирают (E0-12F, круг 3). Ещё - боевые формы роута `apps/api/src/routes/health/index.ts` и `apps/api/src/routes/system/index.ts`: их читают пробы S13/S14 как пропуск, и проба требует, чтобы каждая выбирала `harness-selftest` (E0-12D). Точный glob - гейт `harness-selftest` в `rules.sf.json`; `turbo.json` пробы не читают (E0-01A, E0-02A) |

Только полный прогон (без `--only`) ставит `lastGates`; частичный - для работы, замок его не видит.

Пробы выбора гейтов в `harness-selftest.js` берут `selectGates` из самого `gates.js` (`module.exports`; `main()` и `process.exit` - только под `require.main === module`), а не исполняют скрипт в `vm` (E0-12D). Что `require` не запускает гейты, не ставит `lastGates` и не зовёт `process.exit`, сторожит отдельная проба: в дочернем процессе она подменяет список изменённых файлов, запуск команд гейтов и `process.exit` и требует ноль запусков, ни одного выхода и ни одной отметки; пока она красная, пробы выбора `gates.js` не грузят. Строки пробы одного гейта начинаются с `гейт <id>:`. Пробы `standards.js` пишут файлы не в боевые `src`, а во временное дерево с копией `.claude/hooks`; последняя проба сверяет снимок дерева до и после прогона: записи `git status` с отпечатком содержимого (перезапись уже изменённого файла видна) и игнорируемые записи `!!`; новый файл внутри уже игнорируемого каталога снимок не видит (TECH_DEBT, E0-12L), правка руками во время прогона даёт ту же красную строку. `standards.js` в дереве пробы идёт с `CLAUDE_HOOK_DEBUG=1`: исключение внутри `L.guard` хук глотает (код 0, пустой stdout - как пропуск), а с этой переменной печатает в stderr строку `hook error: …`; проба, которая читает ответ `standards.js`, на отказе и на пропуске считает красным и эту строку (`HOOK_ERROR`), и код вне 0/2. Временные git-репозитории проб не берут из машины ничего, что исполняет код: `git init --template=`, коммит с `-c core.hooksPath=<пустой временный каталог>`; снимок дерева зовёт `git -c core.fsmonitor=false status`.

## Установка и откат

После любой правки обвязки:

```powershell
powershell -ExecutionPolicy Bypass -File .claude/install.ps1
node .claude/hooks/harness-selftest.js
```

Установщик делает снимок `.claude/` в `../.claude-snapshots/` (10 последних), сверяет модели
у команд и агентов, пишет `settings.local.json` (режим разрешений `bypassPermissions` и
allow-список на `.claude/**`; режим `dontAsk` молча отклонял встроенные запросы Claude Code
на запись в `.claude/**`, и `/auto` не мог вести `.task-current`), гоняет самопроверку. Хуки подхватываются новой сессией.

Откат: правил руками и стало хуже - `git checkout -- .claude/<файл>` (обвязка в git вместе
с кодом); прогнал установщик и стало хуже - `otkat.ps1` (возвращает снимок, `settings.local.json`
в том числе). Отключить всё - убрать блок `hooks` из `.claude/settings.json`.

## Тронул сторожа - покажи живой отказ

Правка хука, правила или порога не сделана, пока не показаны **обе** половины: живой отказ
на нарушении и живой пропуск на чистом входе - в `harness-selftest.js` строкой-пробой.
Проба только на отказ проходит у сторожа, отвергающего всё; проба только на пропуск - у снятого.
И третья половина, где проверка что-то перечисляет: пустой вход - красное, не «замечаний нет».
Исключение - рекомендательные `answer-length` и `remind-format`: запрещать они не обязаны,
их «отказ» - замечание в следующий ход; проба показывает замечание на нарушении и тишину
на чистом входе.

## Копилка уроков

`.claude/qa-index.md` - строка на урок (правило и признак в диффе), читают все ревьюеры и техлид.
`.claude/qa-lessons.md` - полная запись, открывается по номеру. Урок пишется в оба файла
шагом «Документы» `/auto` или шагом 4 `/done`. Урок, целиком выражаемый регуляркой, переезжает
в `standards` (`rules.sf.json`) и из копилки убирается: длинную копилку читают по диагонали.

## Экономия токенов (что из принципов применено)

1. Длинное - в файл дела, в чат - решения (`answer-length`, `output-styles/short.md`).
2. Чтение чужими руками: разведка у `planner`, код у `worker`, ревью у семи подагентов;
   оркестратор читает только их короткие итоги.
3. Ревьюерам - индекс уроков, не журнал.
4. Полный набор ревьюеров в автономном режиме намеренно (дифф никто не читает); сокращение
   только при ручном `/qa zones=…`.
5. Модели по ролям с оглядкой на кэш (таблица выше).
6. Одна задача на сессию, `/clear` между задачами: два контекста в одном портят план и ревью.

## Известные ограничения

- Хуки регистрируются через `${CLAUDE_PROJECT_DIR:-.}` - сессию открывать в корне репозитория.
- `test:int` требует поднятый `docker compose` (postgres, redis); без него гейт честно красный -
  это стоп-условие 4, а не повод выключить гейт.
- Гейт `compose` гонит `docker compose config`: без Docker CLI он красный с текстом
  `check-compose: the docker CLI is not on PATH` - это отсутствие предусловия, а не сломанный
  Compose (сломанный файл даёт `docker compose config failed` с выводом Compose).
- Реальные внешние API (YouTube, Gemini, TTS) тратят деньги: агент ходит в них только для
  смоук-проверок, названных в DoD задачи, и только при ключе в `.env`; иначе блокирует задачу
  как «нет предусловия».
- `db-guard` (стража боевой базы) из newDev не перенесён: боевой базы у проекта пока нет.
  Появится VPS - завести до первого деплоя (задача E0-11/E13).
